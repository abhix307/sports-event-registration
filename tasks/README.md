# Project Task Folder

This folder turns the four-member project plan into actionable, small tasks. Names and dates are placeholders; enter the real team names and actual completion status.

## PDF copies ready to share

- [`WORKFLOW.pdf`](WORKFLOW.pdf) — task order, dependencies and shared completion checks.
- [`GITHUB_WORKFLOW.pdf`](GITHUB_WORKFLOW.pdf) — branch, commit, push, PR, review and merge steps.
- [`MEMBER_1_BACKEND.pdf`](MEMBER_1_BACKEND.pdf) — Flask/backend tasks.
- [`MEMBER_2_UI_UX.pdf`](MEMBER_2_UI_UX.pdf) — six HTML/Jinja and CSS code chunks with exact files, snippets, checks, commits and pushes.
- [`MEMBER_3_TESTING.pdf`](MEMBER_3_TESTING.pdf) — quality-check tasks.
- [`MEMBER_4_DEMO_DOCS.pdf`](MEMBER_4_DEMO_DOCS.pdf) — seed data, setup documentation and demo tasks.
- [`TESTING_AND_DEMO_SEQUENCE.pdf`](TESTING_AND_DEMO_SEQUENCE.pdf) — shared acceptance flow and speaking roles.
- [`README.pdf`](README.pdf) — this task-folder index.

The matching `.md` files are kept as editable source versions. Use the companion [`docs/FOUR_MEMBER_CONTRIBUTION_WORKFLOW.md`](../docs/FOUR_MEMBER_CONTRIBUTION_WORKFLOW.md) for the shareable contribution overview. Mark tasks complete only after doing them. GitHub commit/PR evidence must come from the team's real accounts and activity.
